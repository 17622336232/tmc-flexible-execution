# 等待期间取证与延迟判读

机器人接到巡检任务，首先用正常控制循环看机载图，决定导航、记录和提交。它还可以指出已经进入画面、后面可能要近看的表面，给出材料类型、图中位置和来源照片。新请求真正发出后，调度器检查指令是否允许在当前分支提前拍摄，再用机载图与激光测距提出一个能被导航地图接受的相机位置。每次出发和返回都写入动作日志。机器人保存的是带时间、位姿和哈希的原图。收到正常判断后，只有它点选的图才进入下一次正常模型请求。是否读出正确内容、最终使用哪张图，由实际记录和独立评分确定。

### 物理采集与模型请求的选择

有限模型描述一段有共同返回位置的静态巡检。每个尚未明确的条件有若干结果，每个结果会增加一组需要材料的字段。模型可以把关联条件写在一个联合概率表里。分开写的条件假设独立。每种视角说明能为哪些字段提供材料、是否已有原图、采集代价、未决期间能不能采集和能不能判读。无法明确许可的未决操作被排除。在接入原飞控的仿真中，每次补拍后都需回原位，因此这里采用经过标定的往返代价。姿态变化、视图来源与最终报告均可回查。

在这段任务内选两组工作。第一组在本次请求发出前取得并随请求一起判读，第二组在请求尚未返回时拍摄，原图先保留。各分支之后选择还需要的视角与判读组合。设第一组采集耗时为 $a$，本次请求服务时间为 $q$，等待中第二组采集耗时为 $b$。当前阶段墙钟是 $a+\max(q,b)$。对每一种可能的剩余字段集合 $D$，计算用已有材料和剩余相机动作完成它的最低未来代价 $F(D)$，再加上报告成本 $r$。比较的是整段预计完成时间 $a+\max(q,b)+\mathbb{E}[F(D)]+r$。统计中的真实整项耗时由另一只时钟记录。

如果两条结果路径要求同一组剩余字段，并且原图库存、任务权限和后续代价也相同，就能先把两条路径的概率相加，再计算一次后续代价。在本实现支持的静态模型里，这一步保留精确期望。通用对照逐个条件做带记忆的逆向动态规划，拥有同样的采集和语义操作、共享字段、语义请求分组、先验和终端求解器。两者的最优预计成本应当一致。另一个强预取基线从等待与最佳纯拍摄方案出发，可增加、删除、提升或延后任一视角，并重新评估后续代价。比较时保留了只做物理预取的消融。

### 实现支持的范围

- 在飞行器的实时接口中，捕获的额外照片等 GPT 请求使用后再交给下一次正常决策，边等待边拍可以贯穿多轮。最多两份额外视图，未提前判读。预测代价包含当前未决请求及所提议相机工作的后续部分。剩余常规 GPT 服务按各方案相同处理，真实数据可以推翻该假设。
- 在房间相机接口中，只对明确同时授权早拍和早读的任务开放两图合看。一次照片可以供应多个分支问题。若任务要求先存一张原图再回原位，所有方法在自己的回合中实际取得该图，往返计入整项用时。该接口有独立的仪器检查与感知开发准入条件。
- 当两个相同字段集合在障碍物、原图有效期、对象身份、后验概率或剩余路线上不等价时，以上合并不能直接使用。当前模型不支持自由排列的任意路径、运动物体或任意有环任务。视觉判读仍有误差，期望时长的最优性限于声明的成本模型。
- 实验没有微调 GPT 或 Qwen。历史小型排序器保留在原研究版本。这里检验的是使用现有 GPT-6.1 Terra max 的取证与调度，而非排序器训练收益。

### 相关工作如何影响对照

Speculative Actions 已经研究根据预测提前执行可能的后续动作，待预测正确再采用结果。论文在游戏、电商、网页搜索等环境检验它。我们的原图准入和单机器人返程成本需要另行检验，仅有一次提前动作不足以作为新的算法贡献。[Ye 等，Speculative Actions](https://arxiv.org/abs/2510.04371)

TimelyLLM 将模型生成分段，并根据物理代理的执行进度调度推理服务。其服务端与多代理设置为时间分析提供参照。本项目能够测量一个订阅服务的实际请求区间和单机器人的实际动作，无法从这些记录推断服务端排队或调度细节。[TimelyLLM 作者项目页](https://www.anuragkhandelwal.com/papers/timelyllm/)

复核入口为 `research/flexible_scheduling/workflow.py`、`scripts/continuing_workflow_bench.py` 和 `scripts/continuing_native_report.py`。已暴露任务结果只用于开发。

## 在真实返回事件上重新安排剩余任务

新执行模型分别记录机器人位置、正在进行的移动、已取得的原图、每个判断的状态，以及各个在途请求所用的来源和剩余服务时间。机器人只占用一份运动资源。语义服务容量对所有对照相同。事件模型可同时保留两个在途请求；当前房屋在线开发使用一个实际服务槽位。每个请求可以问同一张原图上的一项或两项已获准判断。取得侧面照片、解释其中某个字段、将该字段写入报告，分别检查相应的前提。每到一次快门、到位或真实模型返回事件，执行器都可重新决定下一次移动、发问或等待。只有任务本身要求返回出发位置时才安排回程。

例如，正面和侧面各有一项必须回答的问题。正面回答肯定后，侧面原图又多出一项允许回答的问题。提前拍侧面可以省返访；是否应该立即读侧面，要看等正面回包后能否把两项侧面问题合问，以及先问侧面是否会更早解锁另一项工作。请求的服务时长、原图保存情况和实际分支共同决定哪种安排较快。两项判断来自不同来源时，这一版不给它们合问。

在静态任务、明确来源、独立的已声明结果先验和给定服务成本下，两个过去的结果组合可以产生完全相同的后续问题。实现先用已确认的结果化简所有分支条件。若剩余条件、已答状态、仍受许可限制的提前读数、可用原图、位姿和在途动作都相同，就可以复用后续完成成本。这是因为两种状态许可的下一步相同，每一步耗时及后续结果分布相同。沿有限的剩余事件递推，最优未来成本也相同。每条实际轨迹各自保留带原图指纹的报告内容。需要对不同历史使用不同的后验、原图过期时刻或后续移动代价时，这个等价条件须增加相应状态。

通用条件规划器使用相同的事件、动作、请求合并、先验、合法性检查及代价下界。两者在均完成精确搜索时应得到相同的最低预计用时。研究差异在于计算有界时能否减少重复求解，保住更好的可行方案。第一轮固定节点预算的 76 个配对中，双方都证明最优的 50 个配对全部相等；单边取得证明的有 3 个，均为剩余条件合并版。只有 2 个配对的可行预计用时不同。它们来自模拟的双服务槽位，多字段合问耗时较长，不能推出当前单服务房屋任务也会有同样差距。逐项复核见 `scripts/continuing_concurrent_workflow.py`，实际时钟和适用范围在登记文件中。[受控任务登记](../config/concurrent_workflow_dev01.json)

新房屋开发任务公开给各方法相同的工作单，以便把语言理解和执行顺序的变化分开。串行对照可以合法合问，强预取能比较连续两次调度后的完整后果，通用最优解也参与事前比较。原版飞行器的自由指令执行对照单独保留。单图成本标定采用两个以前暴露的公开验证房屋，用另外两个房屋执行新任务。各判断都用本回合实拍图，全部回合结束后独立检查实例分割、视角、权限、来源指纹及完整报告。[匹配开发任务登记](../config/matched_event_rooms_dev01.json)
