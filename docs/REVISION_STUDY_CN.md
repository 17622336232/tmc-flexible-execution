# 修订实验的读法

论文要回答的问题是，机器人等一个视觉判断时，能否依法先做一部分将来可能需要的现场工作，而且让整项任务更早正确结束。最快开始移动、最快拍完一张照片、最快交付一份正确报告，是三个不同的时刻。

## 三个对照

原版直接让 GPT 看机载图、决定下一步、记录证据和提交。开发入口从上游原始 Git 对象加载控制循环，模型请求走相同的计量接口。第二个对照使用共同执行器，允许去拍本来就需要的下一张照片。第三个对照 A 也能在判断未回时，比较不同结果各自缺什么，先做一个有许可、预计合算、并且每个结果都还有可行后续的动作。A 在每次真实返回后处理实际分支。程序只凭证据核验结果更新事实。三者用同一模型、同一仿真输入与评分。通用规划器另外参加，拥有相同技能、时钟、权限和分支信息。

新实现允许先做一个有价值的动作，另一个分支的材料等结果回来再取得。一个逐步执行的反例测试中，旧共同终点条件拒绝先做动作，修订 A 与通用规划器均找到可行解。这个例子解释了两种算法的差别，也说明通用规划器可能同样有效。在线单个判断仍绑定单个物体。多判断联合调度的现有验证来自离散事件开发环境。

## 原工程的材料

- 两个原工程的控制器文件 SHA256 相同，前八位为 6fb09584。精简工程中的 Gazebo 传感器自检有照片，结果记为未评任务。Diff-VLA 当前 artifacts 内的 44 个 result.json 未记录该任务控制器的 family、policy、model 组合。其迁移日志记载了完整复制，当次目的目录当前不存在。
- Diff-planner-baseline 提供导航源码和录包。Elastic-Tracker 实际位于 /data/nv/Elastic-Tracker。没有从这两个目录找到成套 GPT 巡检任务成绩。
- 本项目保留同一裂纹场景的两次串行复现，150 秒未完成，300 秒通过，两次原评分和严格重评一致。另有一套带额外视觉前段的串行对照覆盖 24 个任务族，原始尝试数、可重评数、缺报告数分别列在 shared_fixes.json。分母是尝试数，其中包含重试，不代表 43 个独立场景。
- 对照差异还包括目标数、任务措辞、布局和期限。旧正式的结构组含组合任务。原用户对旧任务完成度的印象不能换算为同难度、同限时、同证据标准的原版成功率。

## 七项工作的实验做法

| 工作 | 作者使用的数据或实验 | 本项目采用的检验 |
|---|---|---|
| TypeFly | Tello、边缘计算机、语言指令和可执行的 MiniSpec。对比生成与真实动作的时间。 | 记录首次有效动作和最终完成时刻，保留流式基线。[作者公开稿](https://arxiv.org/html/2312.14950v2) |
| SRDrone | 行为树、连续状态反馈、软硬件在环及配有 Orin NX 的实际无人机。 | 区分改变计划、完成动作、任务验收。实机单列测量。[作者公开稿](https://arxiv.org/html/2508.15501v1) |
| TimelyLLM | 多种实体 I/O 工作负载上的分段生成和服务端调度。 | 用真实回包测量阻塞，单机器人客户端的 STREAM 只对应其中一部分机制。[作者发表页](https://www.anuragkhandelwal.com/papers/timelyllm/) |
| Hi Robot | 高层策略用合成指令扩充监督，低层策略执行技能，在单臂、双臂和移动双臂平台验证。 | 把指令是否理解正确与整项任务是否执行成功分开计量。[作者说明](https://www.pi.website/research/hirobot) |
| SELP | 自然语言到时序逻辑的任务，生成规划数据，并用合规且高效的计划微调规划模型，分别评估约束满足与效率。 | 权限用正例、反例和近义表达单独检查，再用全任务评估开销。[作者论文](https://arxiv.org/html/2409.19471v1) |
| InteLiPlan | 自建文本化机器人规划及失败恢复样本，通过 LoRA 微调轻量规划器，测试失败解释、恢复和跨平台。 | 区分感知失败、执行失败和恢复失败，并报告端侧资源。[作者公开稿](https://arxiv.org/html/2409.14506v4) |
| Speculative Actions | 预测软件代理可能采取的动作，提前执行，正式决策后判断是否采用。 | 与强预取比较。单台机器人移动后的位姿、补做和返程时间均计入。[作者公开稿](https://arxiv.org/html/2510.04371v1) |

本项目这次调用现有 GPT-6.1 Terra、max。开发中的 A 使用普通程序比较候选。离线训练的小排序器节省候选检查次数，历史记录未显示它能缩短完整任务。没有微调 Qwen；与上述工作比较的是实验设计和机制，各论文的分数不能直接横比。

## 实体平台边界

Diff-VLA 的 real_ros 执行器有里程计时效、遥控器状态和独占控制检查。主实验仍使用 CPU 渲染的相机和原导航接口。实机需要把任务时钟、带时间戳的原图及姿态、目标可达性、动作完成或失败反馈和人工接管接入同一记录。无人车还需要地面可达路线，机器狗还需足端与稳定停靠能力。此次未观测到这两种平台的闭环数据。无人机在空时间、电流积分能量、Orin 内存及接管次数都需要现场采集。所有实体运动需现场操作者确认。

## 复核入口

在仓库根目录使用已配好视觉仿真依赖的 Python，令 PYTHONPATH 包含 bridge、research/attack_learning 和仓库根目录。

```sh
python -m experiments.flexible_execution.revision_audit
python scripts/revision_validation.py
python scripts/revision_mechanisms.py
python scripts/revision_split.py
python -m experiments.flexible_execution.revision_jobs
```

前四项分别生成历史漏斗、冻结回复与原图重放、十类机制的符号开发结果、隔离候选房清单。最后一项只显示自然在线作业状态。登记的八个开发回合可用 revision_jobs --run 续接。已评分的任务从原产物恢复。结果目录为 outputs/revision-study。

完整请求表使用 `python scripts/revision_raw_cost.py`。457 次原始尝试覆盖 456 个逻辑回合，3,842 次出站请求都有记录。未发现一次成功请求返回后，提示、输入、图片、模型和推理强度全部相同的再次发送。相同物体换角度、重复询问同一含义、报告与核验分别调用，仍可能增加成本。原始日志没有逐请求 token 用量字段。

`python scripts/revision_camera.py` 使用已保存的 RGB、类别、模型输入和原始分割图独立重算公开房屋视觉题。正面共 95 次发送，93 条可评分，正确 81 条，漏看 9 条，误认 3 条，另 2 条没有可评分的绑定回复。它们覆盖 24 个房屋来源组、45 个不同的照片和类别组合。侧面可评的 23 条全部正确，来自 6 个房屋和 12 个不同的照片和类别组合，侧面的样本受到前序分支选择影响。

`python scripts/revision_report.py` 生成按方法的成本、任务族和变化组表，以及离线延迟与运动成本曲线。`python scripts/revision_provenance.py` 核对所有新原版调用的原始提示指纹、去除本地资源路径差异后的世界指纹、图像纹理与指令的逐臂一致性。`python scripts/revision_examples.py` 从仿真相机原图重建可追溯案例图。

完整复核命令是 `bash scripts/verify_revision_study.sh`。它读取本机保留的原始回合、请求和符号轨迹，重建论文表图，不发送模型请求。开发层的独立枚举位于 `scripts/revision_decisions.py`，它对还未揭晓的结果按各分支求期望，只在接到回复时区分分支。初始决策核验是名义可读条件下的有限状态实验。需要重做独立计算时运行该脚本；需要从头生成开发轨迹时运行 `scripts/revision_mechanisms.py` 与 `scripts/revision_ablation.py`。搜索时间为本机实测，重新生成轨迹时会有微小变化。

第三轮本地文字解析默认关闭。预登记的开发入口 `python -m experiments.flexible_execution.revision_jobs --round3 --run` 对三臂提供同一冷解析器，只接受完整识别的措辞和字段类型。出现未知附加限制或无法表达的组合条件时，仍调用原共同模型前端。第三轮结果位于 `outputs/revision-study/round3/`。
