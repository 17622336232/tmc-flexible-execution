# 自然在线基线和论文对应

对照使用本项目同一套导航、相机、状态记录、模型配置、采集许可、任务期限、请求上限和独立评分。所有方法先编译任务并绑定真实观察，之后使用各自取得的有效事实进入整项控制。正式回合独立冷启动。提前移动、补拍和返回任务终点均计时。

| 方法 | 等待期间的实际决策 | 回包后的处理 |
|---|---|---|
| ASYNC | 已获准的独立工作可继续。已有可达的下一目标初始观察位时，可以移动和拍照。 | 按真实条件补所需材料，并完成整项报告。 |
| PREFETCH | 从可能分支的材料并集中提出合法动作。用同一时钟比较候选的预计整项代价，计入一个机器人实际执行的移动。 | 实际分支揭晓后核对已拍材料，可在当前位姿补做或恢复。每一分支分别判断是否能在期限内完成。 |
| PLANNER | 通用有界最佳优先搜索，同一可见候选、时间、分支、终态和预算。允许分支各有可行后续。 | 复查当前位置、分支许可及材料读数，补齐缺项后交接。 |
| STREAM | 先完成一份可执行的动作包。后续真实推理开始后释放已通过检查的导航动作。 | 续段基于相同冻结输入，移动到位和新观察由后续实际反馈提供。 |
| OURS（A） | 从当前任务尚需材料生成候选，验证各可能分支在共同许可下仍可完成，再比较预计代价。 | 只接收与冻结问题原图绑定的判断。没有合法或划算的动作时等待，之后继续整项任务。 |

PREFETCH 已具备风险约束下的预测准备、实际回包核对和不匹配后补做。预测来自候选、可见代价和可能分支，候选生成与检查计入运行开销。所用风险模型、证据接口、期限与分支可行性记录在 `live_planning.py`、`search.py` 和 `adapters/live_inspection.py`。本修订沿用该槽的原有策略，修复所有方法共用的记录交接。

## 与原论文的对应

- TypeFly 的 MiniSpec 解释器能执行已成形的语句，并在缺少语义信息时发起查询。这里复用了按需调用、动作与生成可以重叠、首次响应和整项完成分开计时的实验思路。MiniSpec 语言、Tello 载体和边缘技能服务留在原论文范围。 [作者公开稿](https://arxiv.org/html/2312.14950v2)
- TimelyLLM 调度服务端分段生成以配合物理动作。STREAM 是客户端适配，对一次导航分别发送动作包与续段请求。实际发送和动作重叠可按时间逐项复算。TimelyLLM 的服务端调度、排队和共享前缀优化未在这里复现。 [作者发表页](https://www.anuragkhandelwal.com/papers/timelyllm/)
- Speculative Actions 用较快的预测者提出候选，提前调用并在实际动作揭晓后选择匹配分支。PREFETCH 用现场任务候选及规则估计预测有用工作，遵循物理许可并为补做计费。论文的模型预测器、多分支软件隔离和匹配后的提交机制在原实现中评测。当前一架机器人依次执行真实动作。 [作者全文](https://www.cs.columbia.edu/~kkaffes/papers/speculative-actions-iclr26.pdf)

自建主比较保留五法。公开房间接口的预登记任务只有一次条件侧视和四法对照，OURS 使用同接口的 A。
