# TMC 执行修订与实验协议

研究问题是机器人等待真实判读时，许可内的准备工作能否降低完整任务的受限完成代价。候选动作、真实判读、材料可用时刻、任务完整性和失败都按原始记录核对。

## 版本与预算

- `protocol-v2` 原开发目录保留五个已结束回合、七次启动和 65 次发送。原工作目录和回包继续接受审计。
- 新共同执行器登记为 `evidence-handoff-r1`。同版开发仍是三个场景、12 臂。迁移原未完七个逻辑槽，继承尝试次数、时限和真实请求。首场景五臂从第 1 轮修复额度支付，至多 120 次真实发送。第 2 轮目前登记零个。
- 每臂仍使用原场景期限和 24 次真实发送上限。模型保留 GPT-6.1 Terra（max）。正式主比较 456 臂上限 10,944 次发送，当前登记额外臂为零。一个仿真 worker。
- 在真实发送前运行修订预检，核对独立冻结目录、源码和提示指纹、模型、父账本及原盲选名单。预算迁移后原开发入口封存。已落盘的旧评分和原始照片仍可重算。

```bash
python3 -m experiments.flexible_execution.cli acceleration-audit --current-v2 --out outputs/protocol-v2-optimization/audit
python3 -m experiments.flexible_execution.cli acceleration-audit --revised-v2 --out outputs/protocol-v2-optimization/revised-audit
python3 -m experiments.flexible_execution.cli acceleration-revision-preflight
python3 -m experiments.flexible_execution.cli status --profile local5060 --protocol protocol-v2
python3 -m experiments.flexible_execution.cli continue --profile local5060 --protocol protocol-v2 --resume --max-jobs 12
```

## 共同执行器

前置阶段产生的可核对观察进入现有记录和证据账本。记录包含实际对象身份、事实字段、原始照片和发送哈希、请求序号、真实回包可用时刻和有效区间。当前仅在静态仿真回合交接具有身份关联的明确字段。临时目标号、含糊复合判断及未读到的事实仍待解决。场景状态变化或证据过期时撤销记录。在线终验仍按原要求核对全任务，结束后的独立评分重新走原始照片、请求和报告。公用改动与 A 的调度贡献分列。

P0 发现 34 笔发生在整项控制器接管以后。13 笔在首轮报告拒绝之后，其中包含合理补做。只观察到 1 笔完整输入重复，来自同一编译请求的传输重试。分组照片核验和合并终审均无实测发送，保持原实现。无进展停机、换模型和提示精简留待对应证据支持。

原 v2 的 2 次整项视觉验收返回缺项，合计 194.6 秒。新版前 7 个终态回合有 5 次这类反馈，合计 378.9 秒，均涉及初始范围内另一台设备缺少对象级判读和图像关联。部分旧判断使用临时定位标签，真实设备编号仍未核验。这些观察保留在原始记录中，继续由共同控制和视觉验收查缺。逐请求表保留原反馈和发送时长，供比对超时与实际返回的拒绝。

新版请求剖析采用相同用途分类和账本核对。尚在运行的尝试列为未结算，已完成的请求和暂时失败的尝试按各自原始终态保留。

## 证据层级

| 层级 | 材料和可回答的问题 |
|---|---|
| L1 | 原符号训练组、独立结构/布局和原始候选池。比较排序合法性、检查次数、耗时和预计代价。 |
| L2 | 绑定的真实事件、原图、回包与动作。保留虚拟时钟和删失。新视角及未观察转移标为 `OUT_OF_SUPPORT`。模型化扫描按假设另报。 |
| L3 | 自建及公开交互仿真。方法选动作后才获得对应的相机观察和真实当次模型返回。报告内容、证据、时序许可和硬约束共同评分。 |
| L4 | 经授权的代表性实体任务。当前交付接线和计量设计，实际结果以未来现场记录为准。 |

已采照片上的当次推理归固定输入评测。符号样本和帧的数目不当作独立实体场景。TypeFly 让按需查询动作进入真机任务时间，SRDrone 分开部署闭环与已采失败集合。Hi Robot 使用离线形成的训练材料并单独评估实际机器人任务。HomeLLaMA 的 DevFinder 支持规划端评测。 [TypeFly 作者公开稿](https://arxiv.org/html/2312.14950v2) [SRDrone 作者公开稿](https://arxiv.org/html/2508.15501v1) [Hi Robot 正式论文](https://proceedings.mlr.press/v267/shi25d.html) [HomeLLaMA 作者公开稿](https://arxiv.org/html/2507.08878v1)

## 开发门槛和正式统计

开发使用同版各场景原作业配置。门槛包含共用管线的真实完整报告、A 的多次原图绑定决策、结构化证据交接、提前允许、提前禁止和无收益或判读不清。前置材料的模型判读与最终通过分开保留。开发方法任务失败保留。共享证据丢失、许可违例和测量错误先追到原因。

正式使用原盲 ID。自建 72 个基础实例，每例五法，其中 A 对 PLANNER 是主确认性比较。公开 24 所独立房，每房一个预登记任务、四法，作为单独的外部验证。公开任务覆盖单条件侧视能力。按来源组或房屋配对。方法顺序在场景内预登记，三层自建结果分别汇总。学习和训练量继续在 L1 检查。

结构层覆盖三个固定组合族，包括裂纹和温度的合取后取最值、两个颜色和数量条件的组合，以及校园通道与灭火器状态的组合。场景层覆盖十个任务族，变化包括布局、材质和目标个数。执行条件层有 12 个 360 秒和 12 个 600 秒的场景。结构结论限于已登记的组合和来源，配对聚类按实测来源组处理。

按冻结指令复核，自建只有 3 个场景明确允许提前取得本体编号，都在执行条件层的 600 秒裂纹场景中。其余自建指令按缺少明确提前授权处理。本次盲选未抽到使用显式阳性后取证条款的场景。所有 24 个公开场景均明确允许提前拍侧面照片。自建样本整体可比较同场各方法的任务表现。提前许可集中在一个任务族和一个时限，单独估计许可变化的效果需要更多独立条件。逐场清单和冻结校验值保存在 `outputs/protocol-v2-optimization/formal-progress/registered-permissions.json`。

主要时间指标以成功回合的完整任务时间和未有效完成回合的原时限组成。与此同时，报告实际任务墙钟、完整通过率、先动时间、被最终采用的材料、无用早动作、补做动作、真实发送及独立评分耗时。每场景差值先按来源组归并，报告效应与 95% 自举区间以及登记的自建配对检验。公开及其余基线结果作为验证或探索性结果。发现可检测效应的估计与 72 个独立来源的假设保存于 `development_power.json`。样本少时报告参数假设和估计边界。

动作与前置判断按原图和真实回包绑定。逐回合表分别统计回包前开始的动作、回包前完成的动作、回包前完成的照片采集，以及经完整验收的报告是否采纳这些照片。方法汇总同时标出具有机制计量的回合数。公开场景的这组计量使用独立复核通过的回合。

自建任务按绑定判断统计基于当时许可和预测代价的条件，包括允许且预测可节省、允许但未找到有收益的动作，以及明确需要先确认。策略已经收到回包和提前移动后仍需补做属于事后解释指标。两类计数一起用于复核机制，整项时间和成功率的确认性比较仍使用原登记场景和方法。

自然任务时间包含商业服务等待、真实移动及在线验收。实验活跃时间收录全部尝试、启动、退出和独立评分。日历时间包含额度中断和人工暂停。正式任务启动后出现服务中断时，保存当次尝试并在受限代价中按预登记的失败规则处理。恢复额度后继续下一逻辑作业，并保留跨服务时段块的标记。

同一进程内的传输重试继续计入这一回合的连续任务时间。进程在已开始的任务中因传输超时、网络故障、响应中断或服务过载退出时，以该次原始尝试记录中断失败。11 月 26 日在 `custom-structure-025` 的流式回合验证了这一规则。初次尝试耗时 240.5 秒，两个实际请求均超时。误重启的额外尝试保留在原始账本中，资源合计为 278.2 秒、3 次发送。受限代价沿用该场景原期限。两次尝试与计量修正均可通过控制账本追溯。

冻结模型编译复合任务时若实际回复 `conditional.status=unsupported`，且执行器据此退出，则按该次模型响应记录任务失败。`custom-structure-082` 的普通异步回合首次触发这项分类修正，原请求耗时 112.9 秒、发送 1 次。正式编译、执行和验收继续使用已登记版本，原回复及修正记录保留在控制账本中。

该回复同时给出了带裂纹及温度字段的任务程序。联合提示对无法调度为单对象判读的条件要求填写 `null`，随后引用的单独判读提示要求填写 `status=unsupported`。冻结执行器对两种回复走不同路径。`null` 进入整项控制，`unsupported` 在前端退出。该差异是已观察到的共用任务编译限制，单列于失败分析。

主分析保留全部预登记终态。敏感性结果单列剔除已知服务中断或实际请求时段跨度高于 60 分钟的场景组。该时间线只用于解释服务波动。

请求耗时图、开发受限代价图、正式任务结果图和配对效应图由 `python3 scripts/plot_v2_optimization.py` 从审计及评分文件生成。正式图按域录齐后生成。

## 代表性真机衔接

现场授权后，A 和 PLANNER 复用同一相机及原导航底层。相机适配接 `observe()`，返回原始 JPEG、帧编号、采样时间、采样位姿及图像几何。动作先经 `check_goal()` 核验，再经 `move()` 锁定到达结果。现场传感器保留独立来源标记。位置和姿态与图像配对，底层拒绝、控制接管和退出均写入同一回合。

| 代表性条件 | 复用任务 | 现场验收记录 |
| --- | --- | --- |
| 允许提前且预测有益 | 裂纹后报告设备编号 | 同一原图绑定真实回包，记录拍号动作起止、照片、完整报告和终点 |
| 确认后才允许取证 | 裂纹后的编号采集 | 逐动作核对许可来源、阳性回包及取证顺序 |
| 等待更省 | 同一任务增加备选观测位的代价或缩短判读等待窗口 | 记录当时的可行动作、预测代价、实际选择和完整时间 |
| 判读不确定 | 标号或裂纹局部遮挡 | 记录不确定回包、复查位置、补采照片、最终报告状态 |
| 提前材料随后弃用 | 允许先拍号的设备最终判为无裂纹 | 记录照片成本、弃用原因和完整任务结果 |
| 多次待判读 | 同一排多台设备或连续盘点目标 | 逐条记录原图、真实回包、许可、动作与结果归属 |

仿真接线证据从新版开发回合复核。`pilot-report` 读取 `timeline.jsonl` 中的许可、动作和相机事件，将原始照片哈希与 `model_calls.jsonl` 的发送、回包和独立验收对应起来。现场还需记录每次操作者接管与机载电量实测。相同场景内交错运行 A 和 PLANNER，各自保持同一任务要求、底层约束和计时起点。

强基线的具体动作、各论文实现差异以及共用约束见 [基线对应](BASELINE_EQUIVALENCE.md)。
