# 方法和运行边界

## 当前实际轻量攻击方法

初始外部RGB经一次静态模型解读；在线只使用实际外部RGB、像素行为历史、可见静态上下文和公开时钟。任务假设权重由本地树模型估计，条件评分器为各假设下的候选物理修改评分，再由学习等待策略比较现在行动、继续观察和放弃。每回合最多修改一次。

当前假设词汇是有限的。条件评分和等待收益主要来自自有正常执行轨迹上的读取/采用反事实代理，不代表对每个动作都真实重跑过攻击。机器人遭修改后可能改变路线、复查或恢复，仍需真实完整任务验证。

任务机器人独立使用机载RGB和实测几何，通过共享工具自主观察、移动、记录和提交。飞行规划、传感器时效和安全规则保持在原执行链中。事后评分器保存授权要求和独立事实，不向在线模型提供答案。

## 原完整方案

完整方案用一套共享执行模型：K学习读取、绑定、核验和提交的状态变化；D学习采集与处理时长；E学习执行状态对应的外部可见事件。模型同时用于行为解释、相同状态下修改/不修改的成对终点推演，以及未来观察收益计算。

完整状态应包含目标、来源关系、控制实现、当前操作、操作时长和证据记忆，尤其区分当前来源、已拍下的快照、对象绑定、冲突和独立核验。已经拍下的图像不能因后来环境变化而改变。

仓库当前轻量模型用判别式任务权重、条件效果评分和独立等待学习近似这些环节，未完整复现共享K/D/E、同状态成对执行终点和同模型生成的观察树。目录中其他研究模块也不能因为存在文件就视作完成了完整方案。

## 不同实验入口

- `run_attack_showcase.sh`：当前可视化入口；本地学习攻击需要自己的导入模型。
- `run_inspection.sh`：早期通用API任务/观察者原型，用于无本地权重的链路检查。
- `run_attack_integrity.sh --backend cpu`：CPU渲染与原ROS规划链，和Gazebo结果分别报告。
- `experiments/task_attack/visual_baselines.py`：UAO/ICCV思想的黑盒API适配，不代表原论文的白盒梯度与完整优化目标。

没有随源码发布任何历史实验成绩。新的构建/数据/账户/模型配置应运行独立实验并保存完整分母，不能从示例场景或一次物理修改确认推导方法优越性。
