# 24 项旧任务的接口覆盖

48 个开发实例保留了每个任务的两档场景。整项巡检和离线评分仍走原接口。下表说明哪些语义能进入条件材料调度，实际完成数以每个回合的原始记录为准。

| 任务 | 需要表达的条件与范围 | 条件材料接口 |
| --- | --- | --- |
| cracks | 检查整排，发现裂纹时报告编号和证据 | 可编译单物体判断和条件编号，旧指令未明确授权提前取证 |
| temperature | 检查整排，超过阈值时报告真实数值与编号 | 可编译阈值判断并另存实际数值，旧指令未明确授权提前取证 |
| locate | 只访问指定编号并读取温度 | 需要直接数值查询和单对象覆盖验证 |
| inventory | 对所有货位报告实际箱数 | 需要多对象计数和集合汇总 |
| color_search | 按颜色筛选，报告货位、颜色与箱数 | 可表达颜色筛选，需验证数值和标签来自同一货位 |
| order_check | 对所有货位比较订单与实际数量 | 需要数值查询、公开订单绑定和不等比较 |
| parking | 黄色禁停区域且实际有车，附车辆颜色 | 需要分别保留区域和车辆两个事实、位置关系及未知值 |
| blocked_exit | 查找所有实际堵塞的通道及其编号 | 可编译单通道判断和条件编号，旧指令未明确授权提前取证 |
| fire_safety | 查找所有缺灭火器的消防点 | 可编译单点判断和条件编号，需保留未知与缺失的区别 |
| crack_and_heat | 同一设备同时有裂纹且超温 | 需要两个观测与合取，单项未知时仍保留另一项真实事实 |
| thermal_minimum | 比较整排数值并保留所有并列最小值 | 需要多对象数值与归约 |
| safe_equipment | 同一设备无裂纹且未超温 | 需要两个观测和双重取证，保留否定与未知的区别 |
| shortage | 实物箱数小于每处订单箱数 | 需要直接计数、公开订单键和小于比较 |
| overstock | 实物箱数大于每处订单箱数 | 需要直接计数、公开订单键和大于比较 |
| large_inventory | 每处箱数超过阈值才报告 | 可表达局部阈值，仍需保留实际计数与整排覆盖 |
| vehicle_search | 按实际车辆颜色筛选并关联正确车位 | 需要区分车辆与车位身份并验证占位关系 |
| clear_exit | 全部通畅的通道及编号 | 可编译单通道判断，需保留未知与通畅的区别 |
| fire_and_access | 同一点位有灭火器且可通行 | 需要独立观察、对象关联及合取 |
| locate_crack | 只检查指定编号，报告裂纹判断 | 可表达二值判断，依赖指定编号与画面可靠关联 |
| locate_condition | 指定设备的裂纹与数值温度 | 需要联合布尔和数值输出 |
| locate_boxes | 指定货位的箱数和颜色 | 需要直接计数与颜色输出，第一组真实配对两臂均使用整项巡检回退 |
| locate_order | 指定货位的实物与订单箱数 | 需要直接计数、公开订单绑定及两字段输出 |
| locate_extinguisher | 只检查指定点位是否配备灭火器 | 可表达二值判断，依赖指定点位与画面可靠关联 |
| locate_access | 指定校园通道是否堵塞 | 可表达二值判断，依赖指定通道身份与遮挡区关联 |

另外三项纯读牌任务 `equipment_labels`、`warehouse_labels` 和 `campus_labels` 保留作观察回归，未纳入上述 48 个开发实例。当前条件取证的补充开发指令含可机械核验的独立采集许可句，和原任务排程分别登记。

条件照片判读与整项任务程序现在共用字段类型。校园是否有车、是否禁停、是否堵塞、是否有灭火器和设备是否有裂纹均要求明确的真假值。只有相关区域完整可见才可确认缺失。箱数和订单数用非负整数，温度用有限数值。表中所列对象关联、多个视角和整项覆盖仍由对应真实回合验收，进度见 [PROGRESS.md](../PROGRESS.md)。

`pilot-report` 的 `summary.json` 中，`families` 逐项给出每种任务的计划组数、完整配对数、已运行回合、通过数和各类失败。尚待运行的任务也保留在表中。

旧版评分 5 要求单条记录含齐选中对象的必需字段。`legacy_fragment_recheck` 用已有的逐对象事实合并规则重算同版本报告。通过变化核验还需原始模型提交与保存报告一致，所引照片均在该次请求中。逐臂原始评分和冻结终态仍可从原作业记录核对。
